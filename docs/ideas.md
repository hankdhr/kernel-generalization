# 算法候选与创新边界

下列都是待验证提案。现有工作已经覆盖 RL、轨迹学习、经验记忆、任务合成与 profiler 反馈；这些模块本身不构成本项目的新贡献。

## 优先级 1：学习优化变换的适用条件

一次样本不是单独一份最快代码，而是：

```text
任务语义 + shape/stride/dtype + 硬件/编译配置
同一个起始程序 P
只改变一个可解释选择的程序 P' = T(P)
正确性结果 + 交错重复测量的原始延迟
效果：有效 / 无明显差异 / 失效 / 不正确
测量能够支持的适用条件与尚不确定之处
```

初期变换集合：block size、每线程处理量、向量化访问及对齐约束、warp/block reduction、共享内存布局、融合/拆分。一次多项修改必须单独标记，不纳入单因素效果证据。硬件级 profile 能帮助解释，但不能用 LLM 的文字解释代替测量。

令 z 包含任务和实现条件，定义测得的变换收益：

\[
\Delta(z,T)=\operatorname{median}_j\log\frac{t_j(P,z)}{t_j(T(P),z)}.
\]

通过交错测量与重复会话估计不确定性。只有测量区间明显偏离零且通过正确性检查，才构造“偏好有效”的训练标签；接近噪声的样本标为不确定。该值是受控条件下的程序变换效应，不代表已经证明抽象文字规则的因果性。

### 首个可实现版本

1. 在 train 任务上生成起始正确程序，记录失败成本。
2. 从同一程序出发应用一个变换，同时保留成功和失败候选。
3. 在多个预先定义的 train 条件下测量，寻找效果变化。
4. 生成结构化证据：条件、预测、修改后的代码和测量标签；标签由测量决定。
5. 用相同初始模型进行 SFT：学习条件判断及代码修改。对照使用相同来源的最佳代码，匹配 token 和训练计算预算。
6. 在 dev 选配置；冻结后在 test 用完全相同的 prompt/tools/budget 评估，关闭经验检索。

训练目标的最小形式是证据标注样本上的 token 交叉熵。可加入单独的条件预测任务；必须消融辅助文字是否有用。不要先引入复杂自创 RL 算法，因为数据结构本身的收益尚未证明。

### 最关键的消融

- 最佳代码 SFT：排除“只是更多好代码”。
- 完整轨迹 SFT：排除“只是看到了失败信息”。
- 随机打乱条件标签：检查真实条件是否必要；保留同样文本量。
- 移除失败/反转样本：检查负例价值。
- 仅检索同一份经验：分离参数学习与上下文检索的作用。
- 简单特征模型预测变换收益：检查是否只是几条容易拟合的阈值规则。

**放弃条件：** 等预算完整轨迹 SFT 已获得全部收益；效果只来自近重复任务；关闭检索即消失；条件预测在新任务上没有超过简单基线。负结果仍应公开。

## 优先级 2：主动选择有学习价值的实验

已有条件模型后，优先测试预测不确定、或相近条件下效果可能反转的 (z,T)。与随机采样、只采最快候选对照，匹配编译次数和 GPU 秒。可以从模型集合的收益预测方差开始，无需先设计复杂探索奖励。

核心指标是每 GPU 小时获得多少可迁移提升。只提高候选多样性或训练集速度不够。为防止永远追逐测量噪声，应独立复测、设置噪声阈值，并保存采样概率与拒绝理由。

## 优先级 3：多轮模型自我改进

```text
M0 收集 train 经验 → D0 → 训练 M1
M1 收集新的 train 经验 → D1 → 训练 M2
M2 收集新的 train 经验 → D2 → 训练 M3
```

额外对照：始终由 M0 收集同等数量/成本的数据，再训练；单次合并数据训练；固定经验库重复训练。每轮都用同一未参与优化的监控规则，最终测试集只在方案冻结后统一评估。否则多轮刷新排行榜可能只是选择过拟合。

只有证明更强模型产生的经验更有价值、提升跨轮持续并迁移，才把“自我改进”写进主贡献。递归提升的长期持续性仍须单独论证。

## 暂不作为主线

- “给 profiler 指标加自然语言解释”：与 KernelPro 等工作明显重叠。
- “用 DAG 合成任务然后 RL”：与 DRTriton 等工作明显重叠。
- “在一个固定 shape 上找最快 kernel”：适合作为工程案例，无法支撑模型泛化主张。
- “自发生成 CoT 就是学会硬件原理”：缺乏行为证据，必须通过预测与消融验证。
