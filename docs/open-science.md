# 全流程开源约定

目标是让别人能检查我们怎么得出结论，包括失败实验与决策，而不仅是运行最终最快 kernel。

## 发布内容

- 源码、环境及上游版本锁、命令行、种子、硬件设置、任务生成器和冻结划分。
- 每次实验的计划、模型与 adapter revision、完整 prompt、公开权重模型的原始生成文本/token、候选代码和 hash。
- 编译错误、runtime error、数值错误、超时、无提升候选；每次原始计时和独立 profile 文件。
- 数据筛选规则、丢弃数量及原因、训练日志、checkpoint/adapter、成本和预算偏差。
- 统计脚本、作图脚本、论文源文件，以及主张对应的实验 run 清单。
- 实验账本：日期、假设、命令、commit、成本、结论和下一步。负结果照常发布。

## 数据来源和许可

本仓库原创代码用 Apache-2.0。模型权重、上游代码和第三方任务保留原许可，优先通过固定 revision 下载；不擅自改许可或将第三方全部复制成原创数据。每个训练样本记录来源和派生关系；仅在许可允许时公开其完整内容。采用第三方模型/API 时需先核对条款，不能承诺公开服务方未提供的隐藏推理。

## 目录与发布过程

`runs/` 保存本地完整过程，默认不进入 Git，避免大量二进制和凭证误传。**忽略不等于丢弃**：已完成运行应按 run_id 归档到有版本和校验和的数据发布渠道；轻量 `experiment-ledger.csv` 必须进入 Git。

最终公开前进行内容审查：移除凭证、环境变量值、私人 SSH 地址、账号信息和无关个人数据；用公开环境标签替代。这些内容不属于研究复现材料。保持科研数据不变，并给归档生成 SHA256 清单；记录任何必要的删改原因。

每次运行写入新目录，先写 plan 再写 completion，不覆盖旧结果。失败或中断亦保留；不允许为了清理成绩删掉失败 run。复现者可以重放公开任务和候选，但最终评测器需要独立的权限隔离。

## 当前发布状态

只有本地研究仓库。GitHub namespace/repository 尚待用户确定；尚未创建远程仓库、上传权重或发布论文。首轮预算和服务器入口同样待确定。接入 GPU 后先补环境锁和完整轨迹，再进行首次数据 release。
